# catalog Specification

## Purpose
Дать гостю и пользователю публичный каталог открытых опросов с пагинацией,
сортировкой и поиском, не раскрывая unlisted-опросы и не индексируя их.

## Requirements

### Requirement: Только публичные и открытые опросы

`GET /api/v1/catalog` SHALL возвращать только опросы с видимостью `public` и
статусом `open`. Unlisted, черновики, закрытые и скрытые модерацией опросы
MUST NOT попадать в ответ.

#### Scenario: В каталоге только public и open

- **WHEN** в системе есть public+open, unlisted, draft, closed и hidden опросы
- **THEN** ответ каталога содержит только public+open
- **AND** unlisted не появляется в каталоге ни на одной странице

#### Scenario: Пустой каталог

- **WHEN** нет ни одного public+open опроса
- **THEN** ответ `200` с пустым списком и без курсора следующей страницы

### Requirement: Пагинация каталога

`GET /api/v1/catalog` SHALL поддерживать `limit` и непрозрачный `cursor` из
предыдущего ответа. Неверный курсор MUST давать `400`.

#### Scenario: Следующая страница по курсору

- **WHEN** клиент запрашивает каталог с `cursor` из предыдущего ответа
- **THEN** ответ содержит следующую порцию без повторов и пропусков
- **AND** на последней странице курсор следующей страницы отсутствует

#### Scenario: Ограничение размера страницы

- **WHEN** клиент передаёт `limit` вне допустимого диапазона
- **THEN** сервер применяет границы размера страницы из контракта

#### Scenario: Испорченный курсор

- **WHEN** клиент передаёт неразборчивый `cursor`
- **THEN** ответ `400` с ошибкой запроса

### Requirement: Сортировка по новизне и популярности

`GET /api/v1/catalog` SHALL принимать `sort=new|popular`, по умолчанию `new`.
`new` MUST упорядочивать по дате создания от новых к старым, `popular` — по
числу ответов от большего к меньшему.

#### Scenario: Сортировка по новизне

- **WHEN** клиент запрашивает `sort=new`
- **THEN** более новые public+open опросы идут раньше более старых

#### Scenario: Сортировка по популярности

- **WHEN** клиент запрашивает `sort=popular`
- **THEN** опрос с большим числом ответов идёт раньше опроса с меньшим числом
- **AND** каталог не содержит unlisted даже при высоком числе ответов

#### Scenario: Неизвестная сортировка

- **WHEN** клиент передаёт значение `sort`, отличное от `new` и `popular`
- **THEN** ответ `400` с ошибкой запроса

### Requirement: Поиск по каталогу

`GET /api/v1/catalog` SHALL принимать `q` длиной от 1 до 100 символов и
искать по названию и описанию. Поиск MUST возвращать только public+open
опросы и MUST NOT находить unlisted по названию, описанию или slug.

#### Scenario: Поиск находит совпадение

- **WHEN** клиент передаёт `q`, совпадающий с названием или описанием
  public+open опроса
- **THEN** такой опрос есть в результатах

#### Scenario: Поиск не находит unlisted

- **WHEN** клиент передаёт `q`, совпадающий с unlisted опросом
- **THEN** unlisted отсутствует в результатах поиска

#### Scenario: Некорректный запрос поиска

- **WHEN** `q` пустой или длиннее 100 символов
- **THEN** ответ `400` с ошибкой запроса

### Requirement: Unlisted вне индексации

Unlisted-опросы MUST NOT попадать в sitemap. Страницы `/t/<slug>` и `/r/<id>`
для unlisted MUST отдаваться с `noindex`, а публичные страницы MUST NOT
получать `noindex` из-за видимости.

#### Scenario: Unlisted отсутствует в sitemap

- **WHEN** клиент запрашивает sitemap
- **THEN** в нём нет URL unlisted-опросов
- **AND** URL public+open опросов могут присутствовать

#### Scenario: Unlisted отдаётся с noindex

- **WHEN** гость открывает `/t/<slug>` unlisted-опроса
- **THEN** ответ содержит заголовок `X-Robots-Tag: noindex`
- **AND** HTML содержит метатег `robots` со значением `noindex`

#### Scenario: Публичная страница индексируема

- **WHEN** гость открывает `/t/<slug>` public-опроса
- **THEN** ответ не содержит `noindex` для этой страницы
