# self-host Specification

## Purpose
Восстановить требование к self-host tierl: сервис поднимается одной командой,
переменные окружения и секреты описаны, миграции применяются автоматически или
явной командой, health/ready-пробы доступны, а production-деплой описан без
секретов в репозитории.

## Requirements

### Requirement: Запуск одной командой

Система SHALL запускаться из корня репозитория командой `docker compose up`
(в README — `docker compose up --build -d`) без локальных Go, Node.js или
PostgreSQL. Compose MUST собирать `app` из `Dockerfile`, поднимать `postgres`
и публиковать UI/API на порту хоста `TIERL_PORT`, по умолчанию на loopback.

#### Scenario: Быстрый старт с нуля

- **WHEN** пользователь клонирует репозиторий, копирует `.env.example` в `.env`
  и выполняет `docker compose up --build -d`
- **THEN** контейнеры `app` и `postgres` запускаются
- **AND** `app` начинает слушать UI и API на порту `8080` внутри контейнера
- **AND** для запуска не требуются локальные Go, Node.js или PostgreSQL

#### Scenario: Остановка сохраняет данные

- **WHEN** пользователь выполняет `docker compose down`
- **THEN** контейнеры останавливаются
- **AND** данные PostgreSQL в named volume сохраняются, пока не указан `-v`

### Requirement: Порядок старта и готовность базы

`app` MUST стартовать только после готовности PostgreSQL, подтверждённой
healthcheck `pg_isready`. После готовности базы `app` MUST применить
недостающие миграции при `TIERL_MIGRATE_ON_START=true`.

#### Scenario: Приложение ждёт базу

- **WHEN** `postgres` ещё не прошёл healthcheck `pg_isready`
- **THEN** `app` не начинает обслуживать запросы
- **AND** после готовности базы `app` применяет миграции и стартует

### Requirement: Переменные окружения и секреты

Приложение SHALL читать настройки из переменных `TIERL_*` при старте.
Репозиторий MUST содержать `.env.example` с полным списком переменных
приложения и Compose, значениями по умолчанию и комментариями. Реальный `.env`
MUST быть исключён из git. Секреты MUST NOT храниться в репозитории, попадать
в образ или логи; `POSTGRES_PASSWORD`, `TIERL_IP_HASH_SALT` и ключи S3 MUST
быть заменены вне локальной среды. `TIERL_IP_HASH_SALT` MUST быть обязательным,
если задан `TIERL_DATABASE_URL`.

#### Scenario: Конфигурация описана

- **WHEN** новый пользователь открывает `.env.example` или раздел переменных
  окружения в `docs/SELF-HOST.md`
- **THEN** он видит назначение, значения по умолчанию и обязательность
  переменных приложения и Compose
- **AND** описано, какие значения являются секретами

#### Scenario: Секрет не требуется для локального запуска, но обязателен вне его

- **WHEN** сервис запускается локально со значениями по умолчанию
- **THEN** dev-значения из `.env.example` позволяют поднять сервис
- **AND** документация требует заменить пароль базы и соль хэширования IP перед
  публикацией

#### Scenario: Небезопасная конфигурация отклоняется

- **WHEN** задан `TIERL_DATABASE_URL`, а `TIERL_IP_HASH_SALT` пуст
- **THEN** приложение завершается с ошибкой конфигурации
- **AND** не начинает обслуживать запросы

### Requirement: Миграции

Система SHALL применять SQL-миграции автоматически при старте, если
`TIERL_MIGRATE_ON_START=true`, либо явной командой `migrate up` /
`make migrate-up`. Откат MUST выполняться командой `migrate down` /
`make migrate-down` и MUST быть разрушительным. Имена миграций MUST содержать
timestamp и суффикс `_up.sql` или `_down.sql`; уже применённые миграции MUST NOT
редактироваться. Ошибка миграции при старте MUST завершать запуск приложения.

#### Scenario: Автоматическое применение

- **WHEN** `app` стартует с `TIERL_MIGRATE_ON_START=true` и пустой базой
- **THEN** применяются все недостающие миграции
- **AND** при актуальной схеме повторный старт не меняет базу

#### Scenario: Ручное применение

- **WHEN** пользователь выполняет `make migrate-up` с доступной базой
- **THEN** недостающие миграции применяются без запуска приложения

#### Scenario: Ошибка миграции останавливает старт

- **WHEN** миграция завершается ошибкой
- **THEN** `app` завершается с ошибкой
- **AND** не начинает обслуживать запросы

### Requirement: Health и readiness пробы

Сервис SHALL предоставлять `GET /healthz` как liveness-пробу и `GET /readyz`
как readiness-пробу. `/healthz` MUST отвечать `200 ok`, пока процесс жив, и
MUST NOT зависеть от базы. `/readyz` MUST проверять доступность PostgreSQL с
таймаутом и отвечать `200 ok` либо `503 not ready`. Документация MUST описывать
проверку проб и их использование в reverse proxy или orchestrator.

#### Scenario: Процесс жив

- **WHEN** клиент запрашивает `GET /healthz`
- **THEN** ответ `200` с телом `ok`
- **AND** ответ не зависит от состояния PostgreSQL

#### Scenario: База доступна

- **WHEN** клиент запрашивает `GET /readyz`, а PostgreSQL отвечает
- **THEN** ответ `200` с телом `ok`

#### Scenario: База недоступна

- **WHEN** клиент запрашивает `GET /readyz`, а PostgreSQL не отвечает
- **THEN** ответ `503` с телом `not ready`
- **AND** процесс не перезапускается только из-за этой проверки

### Requirement: Production-деплой

Документация SHALL описывать production-деплой: TLS на reverse proxy,
недоступность PostgreSQL из интернета, секреты вне репозитория, отдельный шаг
миграций для нескольких реплик, резервное копирование, обновление и откат
образа. Сервис SHALL поставляться как один образ, собираемый multi-stage
`Dockerfile`, со встроенной статикой SPA.

#### Scenario: Деплой за reverse proxy

- **WHEN** пользователь разворачивает сервис в production
- **THEN** документация предлагает reverse proxy с TLS перед `app`
- **AND** требует не публиковать порт PostgreSQL в публичную сеть

#### Scenario: Обновление и откат

- **WHEN** выходит новая версия
- **THEN** документация требует резервную копию, применение миграций отдельным
  шагом и проверку `/readyz`
- **AND** описывает откат на предыдущий образ без автоматического отката схемы

#### Scenario: Секреты не попадают в репозиторий

- **WHEN** проверяется содержимое репозитория и образа
- **THEN** реальных паролей, солей и ключей S3 нет
- **AND** документация требует хранить их в секрет-хранилище или `.env` с
  ограниченными правами
