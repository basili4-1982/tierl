# author-profile Specification

## Purpose
Дать автору опроса самостоятельное управление своей работой: видеть только свои
опросы, закрывать и удалять их, менять пароль.

## Requirements

### Requirement: Список своих опросов

Система SHALL возвращать автору только его собственные опросы с их состоянием и
агрегатами. Список MUST требовать аутентификации.

#### Scenario: Автор видит только свои опросы

- **WHEN** автор запрашивает `GET /api/v1/me/tierlists` с действующей сессией
- **THEN** ответ содержит только опросы этого автора
- **AND** каждый элемент содержит состояние, число ответов и число элементов

#### Scenario: Гость не получает список

- **WHEN** запрос без сессии
- **THEN** ответ `401`

#### Scenario: В списке нет чужих опросов

- **WHEN** в системе есть опросы двух авторов
- **THEN** каждый автор видит в списке только свои

### Requirement: Управление своим опросом

Система SHALL разрешать закрытие, переоткрытие и удаление опроса только его
владельцу. Для чужого или несуществующего опроса ответ MUST быть `404`.

#### Scenario: Автор закрывает свой опрос

- **WHEN** автор отправляет `PATCH /api/v1/tierlists/{id}` с состоянием `closed`
- **THEN** опрос переходит в закрытое состояние
- **AND** прохождение опроса становится недоступным

#### Scenario: Автор переоткрывает свой опрос

- **WHEN** автор отправляет `PATCH /api/v1/tierlists/{id}` с состоянием `public`
- **THEN** опрос снова проходит по правилам публичного доступа

#### Scenario: Автор удаляет свой опрос

- **WHEN** автор отправляет `DELETE /api/v1/tierlists/{id}`
- **THEN** опрос удалён, повторный `GET` по нему даёт `404`

#### Scenario: Чужой опрос неотличим от несуществующего

- **WHEN** автор пытается изменить или удалить опрос другого автора
- **THEN** ответ `404`
- **AND** опрос другого автора не меняется

### Requirement: Смена пароля закрывает остальные сессии

Система SHALL принимать новый пароль автора и MUST инвалидировать все его
сессии, кроме текущей. Текущая сессия MUST продолжать работать.

#### Scenario: После смены пароля старая сессия не работает

- **WHEN** автор меняет пароль и входит в другой сессии со старым паролем
- **THEN** старый пароль отклоняется `401`
- **AND** ранее выданные сессии этого пользователя больше не действуют

#### Scenario: Текущая сессия остаётся рабочей

- **WHEN** автор сменил пароль из текущей сессии
- **THEN** `GET /api/v1/me/tierlists` в этой же сессии отвечает `200`

#### Scenario: Слабый пароль отклоняется

- **WHEN** новый пароль короче минимальной длины
- **THEN** ответ `400` с причиной
- **AND** пароль и сессии остаются прежними

### Requirement: Страница профиля автора

Система SHALL предоставлять авторизованному автору страницу `/profile` со
списком его опросов и действиями управления. Страница MUST быть доступна только
при действующей сессии; гостя система MUST отправлять на вход.

#### Scenario: Автор видит только свои опросы

- **WHEN** автор открывает `/profile` с действующей сессией
- **THEN** страница показывает только опросы этого автора
- **AND** у каждого опроса видны состояние, число ответов и число элементов

#### Scenario: Гость перенаправляется на вход

- **WHEN** гость открывает `/profile`
- **THEN** система перенаправляет его на `/login`
- **AND** после входа возвращает на запрошенную страницу

#### Scenario: Автор управляет опросом из списка

- **WHEN** автор нажимает «Закрыть», «Открыть» или «Удалить»
- **THEN** действие применяется к его опросу через API
- **AND** список обновляется, а удаление требует подтверждения

#### Scenario: Автор меняет пароль из профиля

- **WHEN** автор вводит текущий и новый пароль в форме на `/profile`
- **THEN** новый пароль отправляется через `POST /api/v1/me/password`
- **AND** после успеха показано, что остальные сессии закрыты

#### Scenario: Ошибка действия видна автору

- **WHEN** API отклоняет действие или загрузку списка
- **THEN** страница показывает сообщение об ошибке
- **AND** не выдаёт ошибку за успешное выполнение
