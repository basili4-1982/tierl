# Spec Delta

## Purpose

Восстановить требование к сквозной приёмочной проверке MVP: один автоматический
тест на чистой БД проходит путь автора и гостя через публичный HTTP API, без
ручных изменений бизнес-состояния в базе, и покрывает unlisted вне каталога и
повторную отправку по контракту.

## ADDED Requirements

### Requirement: Сквозной путь MVP через публичный API

Система SHALL иметь автоматический end-to-end тест, который на чистой схеме
после применённых миграций проходит путь регистрация → подтверждение email →
создание опроса → шеринг → ответ гостя → результат. Шаги регистрации,
подтверждения email, создания опроса, отправки ответа и получения результата
MUST выполняться через публичные HTTP-маршруты. Тест MUST NOT менять
бизнес-состояние прямыми запросами к таблицам или вызовами хранилища в обход
API.

#### Scenario: Автор подтверждает email и создаёт опрос

- **WHEN** тест регистрирует автора и получает одноразовый токен через тестовый
  канал доставки письма
- **THEN** подтверждение выполняется через `POST /api/v1/auth/verify-email`
- **AND** после подтверждения `POST /api/v1/tierlists` возвращает `201`

#### Scenario: Гость отвечает и видит результат

- **WHEN** гость открывает `GET /api/v1/tierlists/{slug}` по ссылке
- **AND** отправляет ответ через `POST /api/v1/tierlists/{slug}/submissions`
- **THEN** `GET /api/v1/results/{id}` возвращает ответ участника и опрос
- **AND** результат доступен без регистрации

#### Scenario: Повторный запуск на чистой БД

- **WHEN** тест запускается после отката и повторного применения миграций
- **THEN** он не зависит от данных предыдущих тестов и завершается успешно

### Requirement: Unlisted вне каталога в E2E

Система SHALL проверять в E2E, что unlisted-опрос отсутствует в публичном
каталоге и при этом доступен по прямой ссылке. Проверка отсутствия в каталоге
MUST использовать публичный маршрут `GET /api/v1/catalog`, когда он
реализован; проверка на уровне `Store.ListPublic` допустима только как
временная замена до появления маршрута.

#### Scenario: Unlisted не попадает в каталог

- **WHEN** создан unlisted-опрос и существует публичный опрос
- **THEN** `GET /api/v1/catalog` содержит публичный опрос
- **AND** ответ каталога не содержит unlisted-опрос и его slug

#### Scenario: Unlisted доступен по ссылке

- **WHEN** гость открывает `GET /api/v1/tierlists/{slug}` unlisted-опроса
- **THEN** ответ `200` с этим опросом
- **AND** доступ не зависит от попадания в каталог

### Requirement: Повторная отправка по контракту

Система SHALL проверять в E2E контракт повторной отправки: повторный `POST` от
той же анонимной сессии MUST возвращать `409 already_submitted` с
`details.result_id`, а `PUT /api/v1/tierlists/{slug}/submissions/mine` MUST
возвращать `200` и сохранять тот же идентификатор результата.

#### Scenario: Повторный POST отклоняется

- **WHEN** сессия уже отправила ответ и повторно вызывает
  `POST /api/v1/tierlists/{slug}/submissions`
- **THEN** ответ `409` с кодом `already_submitted`
- **AND** `details.result_id` указывает на существующий результат

#### Scenario: PUT заменяет ответ без нового результата

- **WHEN** та же сессия вызывает
  `PUT /api/v1/tierlists/{slug}/submissions/mine` с новыми позициями
- **THEN** ответ `200` с тем же `id`, что и у первого ответа
- **AND** число ответов не увеличивается
- **AND** распределение по тирам отражает новые позиции
