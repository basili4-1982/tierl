# Spec Delta

## Purpose

Восстановить требование к сквозному приёмочному пути MVP: автор проходит
регистрацию, подтверждение email, создание и шеринг опроса без ручных
изменений бизнес-состояния в БД, гость отвечает и получает результат только
через публичный HTTP API, повторная отправка следует контракту, а unlisted не
попадает в публичный каталог.

## ADDED Requirements

### Requirement: Путь автора без ручных действий в БД

Система SHALL позволять автору пройти путь «регистрация → подтверждение email
→ создание опроса → шеринг» только через публичный API, без прямого изменения
бизнес-состояния в базе данных. Подтверждение email MUST выполняться через
`POST /api/v1/auth/verify-email` с одноразовым токеном из доставленного
письма, создание — через `POST /api/v1/tierlists`, чтение по ссылке — через
`GET /api/v1/tierlists/{slug}`.

#### Scenario: Без подтверждения email создание запрещено

- **WHEN** зарегистрированный, но неподтверждённый автор вызывает
  `POST /api/v1/tierlists`
- **THEN** ответ `403` с кодом `email_not_verified`
- **AND** опрос не создаётся

#### Scenario: Подтверждение письмом открывает создание

- **WHEN** автор берёт токен из доставленного письма и вызывает
  `POST /api/v1/auth/verify-email`
- **THEN** ответ `204`, а повторный вход возвращает `email_verified = true`
- **AND** после этого `POST /api/v1/tierlists` возвращает `201`

#### Scenario: Гость открывает опрос по ссылке

- **WHEN** гость запрашивает `GET /api/v1/tierlists/{slug}` для созданного
  публичного опроса
- **THEN** ответ `200` с элементами и тирами опроса
- **AND** `is_owner = false`, регистрация не требуется

### Requirement: Приём ответа гостя через публичный API

Система SHALL принимать ответ гостя через
`POST /api/v1/tierlists/{slug}/submissions` без регистрации. Если cookie
`tierl_anon` нет, система MUST выдать новую анонимную cookie. Успешный ответ
MUST возвращать `201` с идентификатором результата.

#### Scenario: Двадцать гостей отвечают через HTTP

- **WHEN** 20 разных анонимных гостей отправляют ответ на один опрос
- **THEN** каждый получает `201`, идентификатор результата и cookie
  `tierl_anon`
- **AND** `GET /api/v1/tierlists/{slug}` показывает `submissions_count = 20`

### Requirement: Результат и повторная отправка

Результат MUST быть доступен через `GET /api/v1/results/{id}`, а статистика —
через `GET /api/v1/results/{id}/stats`. Повторный `POST` от той же анонимной
сессии MUST возвращать `409 already_submitted` с `details.result_id`.
`PUT /api/v1/tierlists/{slug}/submissions/mine` MUST заменять ответ, сохраняя
прежний идентификатор результата и не увеличивая число ответов.

#### Scenario: Гость видит результат и статистику

- **WHEN** гость запрашивает `GET /api/v1/results/{id}` и
  `GET /api/v1/results/{id}/stats` для своего результата
- **THEN** ответы `200` содержат ответ, опрос, распределение по тирам и
  `total_submissions = 20`
- **AND** при 20 ответах `insufficient_data = false`

#### Scenario: Повторная отправка следует контракту

- **WHEN** та же анонимная сессия повторно вызывает `POST`, а затем
  `PUT /submissions/mine`
- **THEN** повторный `POST` возвращает `409 already_submitted` с
  `details.result_id`
- **AND** `PUT` возвращает `200` с тем же `id`, а число ответов остаётся
  прежним

### Requirement: Unlisted вне публичного каталога

Unlisted-опрос SHALL быть доступен по прямой ссылке, но MUST NOT попадать в
публичный каталог.

#### Scenario: Unlisted доступен по ссылке и отсутствует в каталоге

- **WHEN** автор создаёт unlisted-опрос, а затем гость открывает его по ссылке
  и запрашивает публичный каталог
- **THEN** `GET /api/v1/tierlists/{slug}` возвращает `200` с
  `visibility = unlisted`
- **AND** публичный каталог содержит public-опрос и не содержит unlisted
