# Design

## Context

`internal/domain` уже знает про `Item.ImageURL`. Пакет `internal/media`
(появился вместе с закрытым PR #43) реализует `Process` — проверка типа, размера,
сторон и перекодирование — и две реализации `Storage`: файловая система и
S3-совместимый бакет, с `ValidateKey`, `URL` и `Delete`. Пакет ни к чему не
подключён.

Опросы живут в `internal/tierlist` и `internal/storage/postgres`, HTTP-слой —
`internal/web/api`, редактор — `web/src/features/tierlist-editor`.

## Goals / Non-Goals

**Goals:**

- загрузка картинки одним запросом с понятными ошибками (`413`, `415`, `400`);
- байты картинок не попадают в Postgres;
- удаление элемента освобождает файл — хранилище не копит мусор;
- редактор позволяет поставить и убрать картинку элемента.

**Non-Goals:**

- модерация загруженных картинок;
- кроп/редактирование в браузере (перекодирование делает сервер);
- CDN и подписанные ссылки: `Storage.URL` уже отдаёт публичный адрес;
- загрузка картинок тиров и обложек опроса.

## Decisions

1. **Переиспользуем `internal/media` как есть.** Валидация и перекодирование уже
   покрыты тестами пакета; дублировать проверку типа по `Content-Type` в
   обработчике не нужно — `Process` смотрит на содержимое.
2. **Отдельный эндпоинт `POST /api/v1/media`,** а не поле файла в
   `POST /tierlists`: редактор загружает картинку в момент выбора файла, до
   сохранения опроса. Альтернатива — загрузка внутри сохранения — отклонена:
   один битый файл тогда отменяет всё сохранение.
3. **В БД только URL.** Ключ объекта выводится из URL при удалении; для этого
   хранилище возвращает URL, содержащий ключ (`joinURL`/`S3 URL`). Колонка
   с байтами не нужна: бэкап базы не растёт от картинок.
4. **Право на URL проверяется по владельцу.** `image_url` элемента принимается,
   только если это URL, выданный загрузкой этого пользователя (ключ содержит
   `user_id`), иначе `400`: иначе чужой файл можно привязать к своему опросу и
   удалить его вместе с элементом.
5. **Удаление — по жизненному циклу элемента.** При `PATCH`, где элемент исчез
   или у него сменился `image_url`, старый файл удаляется; при `DELETE`
   опроса удаляются все его файлы. Ошибка удаления файла не отменяет запрос —
   логируется: пользователь не должен страдать от недоступного хранилища.
6. **Конфигурация хранилища — env**, как у остальных внешних зависимостей:
   `MEDIA_STORAGE=fs|s3`, `MEDIA_DIR`, `MEDIA_S3_*`, `MEDIA_BASE_URL`. Без
   конфигурации загрузка отвечает `503`, остальное приложение работает.

## Risks

- Публичный URL картинки не защищён: кто знает ключ, тот видит файл. Для
  картинок элементов это приемлемо (они и так показываются в опросе).
- Удаление файла при `PATCH` может не пройти, если процесс упал между записью
  опроса и удалением файла; мусор остаётся, но данные целы. Полноценная
  сборка мусора — отдельная задача.
