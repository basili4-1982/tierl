# Proposal

## Why

Аудит TIERL-59 способности «Прохождение опроса» подтвердил, что требования
R1–R3 (приём ответа, минимум три размещения и неполный ответ, один ответ на
анонимную сессию) реализованы в коде. Живая capability `submissions` уже
существует, но не описывает поведение при отправке ответа на опрос, который не
находится в статусе `open`: `docs/SPEC.md` §3 требует принимать ответы только
для `open`, OpenAPI перечисляет `409 tierlist_closed` для `POST` и `PUT`, а
сервис и хранилище действительно возвращают эту ошибку. В живой спеке такого
требования нет, поэтому часть поведения прохождения опроса не видна при сверке
работы.

## What Changes

- В capability `submissions` добавляется требование «Ответ на закрытый опрос»:
  `POST /api/v1/tierlists/{slug}/submissions` и
  `PUT /api/v1/tierlists/{slug}/submissions/mine` для опроса не в статусе `open`
  MUST отвечать `409` с кодом `tierlist_closed`, не сохранять и не заменять
  ответ.
- Существующие требования R1–R3 не переписываются; якорь `submissions`
  сохраняется без переименования.
- Поведение кода, тестов, HTTP-маршрутов, контракта и applied-миграций в этом
  change не меняется: требование фиксирует уже реализованное поведение.

## Capabilities

### New Capabilities

Нет. Новая способность не вводится: отказ принимать ответ на закрытый опрос —
часть той же цели «Прохождение опроса».

### Modified Capabilities

- `submissions`: добавляется требование к ответу на закрытый опрос, чтобы
  реализованная и задокументированная в `docs/SPEC.md` §3 и OpenAPI проверка
  была видна в живой спеке.

## Impact

- Спека: `openspec/specs/submissions/spec.md` после архивации получит требование
  «Ответ на закрытый опрос».
- Код (только проверка соответствия, без изменения поведения):
  `internal/tierlist/submissions.go:Submit` (`ErrNotAcceptingSubmissions`),
  `internal/storage/postgres/answers.go:Save`,
  `internal/web/api/api.go:writeServiceError` (`409 tierlist_closed`).
- Контракт: `api/openapi.yaml`, ответы `409` для `POST` и `PUT` ответа.
- Аудит: `docs/audits/submissions.md` фиксирует вердикты `ok` по R1–R3 и gap
  спеки, восстановленный этим change.
