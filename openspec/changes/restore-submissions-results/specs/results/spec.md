# Spec Delta

## Purpose

Дать участнику получить свой результат по публичному идентификатору и
анонимную статистику: распределение ответов по тирам, долю «думают как ты» и
порог «мало данных», не раскрывая идентификаторы сессий, аккаунтов, email или
IP.

## ADDED Requirements

### Requirement: Результат по идентификатору

Система SHALL отдавать результат через `GET /api/v1/results/{id}`, где `id` —
непредсказуемый публичный идентификатор ответа. Успешный ответ MUST возвращать
`200` с ответом участника (`submission`) и опросом (`tierlist`); доступ MUST
не требовать регистрации. Для неизвестного идентификатора система MUST
возвращать `404 not_found`. Публичный результат MUST NOT содержать
`session_id`, `user_id`, email или IP.

#### Scenario: Результат доступен по ссылке

- **WHEN** клиент запрашивает `GET /results/{id}` существующего результата
- **THEN** ответ `200`
- **AND** `submission.id` равен запрошенному `id`
- **AND** `tierlist.slug` указывает на исходный опрос

#### Scenario: Неизвестный результат не раскрывается

- **WHEN** клиент запрашивает `GET /results/{unknown}`
- **THEN** ответ `404 not_found`

### Requirement: Распределение ответов по тирам

Система SHALL отдавать в `GET /api/v1/results/{id}/stats` распределение
ответов по тирам для каждого элемента опроса. Для каждого элемента MUST быть
указан его `item_id`, `label` и массив по всем тирам с `tier_id`, числом
ответов `count` и процентом `percent` от общего числа ответов на опрос.
Элемент, который участник не разместил, MUST NOT считаться размещённым в
распределении.

#### Scenario: Распределение содержит все тиры элемента

- **WHEN** клиент запрашивает статистику результата
- **THEN** для каждого элемента есть запись `distribution`
- **AND** в ней присутствуют все тиры опроса
- **AND** `count` и `percent` соответствуют сохранённым ответам

#### Scenario: Неполный ответ не добавляет размещений

- **WHEN** в опросе есть ответ, где элемент не размещён
- **THEN** этот элемент не получает дополнительный `count` в тире
- **AND** процент считается от общего числа ответов на опрос

### Requirement: Порог «мало данных»

Система SHALL возвращать в статистике `total_submissions`, `min_submissions` и
`insufficient_data`. Порог по умолчанию MUST быть равен 20 ответам. Если
ответов в опросе меньше порога, `insufficient_data` MUST быть `true`,
`like_you_percent` MUST быть `null`, а `similar` и `dissimilar` MUST быть
пустыми. При числе ответов не меньше порога система MUST вычислять долю
участников со сходством не ниже порога и MUST возвращать не более 5 самых
похожих и не более 5 самых непохожих результатов.

#### Scenario: Девятнадцать ответов — мало данных

- **WHEN** в опросе 19 ответов
- **THEN** `insufficient_data = true`
- **AND** `min_submissions = 20`
- **AND** `like_you_percent` равен `null`
- **AND** `similar` и `dissimilar` пусты

#### Scenario: Двадцать ответов достаточно

- **WHEN** в опросе 20 ответов
- **THEN** `insufficient_data = false`
- **AND** `like_you_percent` содержит долю похожих участников
- **AND** `similar` и `dissimilar` содержат не более 5 записей каждый
- **AND** запрошенный результат не входит в `similar`

### Requirement: Анонимность публичной статистики

Публичная статистика MUST содержать только агрегаты и MUST NOT содержать
`session_id`, `user_id`, email или IP участников.

#### Scenario: Идентификаторы не попадают в ответ

- **WHEN** клиент запрашивает результат или статистику
- **THEN** тело ответа не содержит `session_id`, `user_id`, email или IP
- **AND** распределение остаётся агрегированным по элементам и тирам
