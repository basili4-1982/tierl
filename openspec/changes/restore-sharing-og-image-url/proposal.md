# Proposal

## Why

TIERL-38 (PR 102) исправил дефект TIERL-30: после переноса публикуемой
OG-картинки на `/og/t/<slug>.png` и `/og/r/<id>.png` серверные тесты
по-прежнему запрашивали алиасы `/t/<slug>/og.png` и `/r/<id>/og.png` и потому
не подтверждали, что ссылка из `og:image` действительно отдаёт PNG. Теперь
тесты берут адрес из `og:image`, но capability `sharing` описывает только
старые адреса PNG и не фиксирует канонический URL превью, поэтому у работы
TIERL-38 нет живой цепочки «цель → спека».

## What Changes

- В capability `sharing` добавляется требование к каноническому URL
  OG-превью: `og:image`/`twitter:image` публикуют абсолютный
  `/og/t/<slug>.png` или `/og/r/<id>.png`, а этот адрес отдаёт PNG 1200x630 с
  теми же cache- и `noindex`-правилами, что и старые алиасы.
- Фиксируется проверка, что серверные тесты запрашивают изображение по URL из
  `og:image`, а не по жёстко заданному старому адресу.
- Поведение кода и тестов не меняется: реализация уже соответствует
  требованию, а старые маршруты остаются совместимыми алиасами.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `sharing`: добавляется требование к каноническому URL OG-превью и к
  проверке изображения по ссылке со страницы шеринга.

## Impact

- Спека: `openspec/specs/sharing/spec.md` после архивации получит новое
  требование.
- Код: `internal/web/api/og.go`, `internal/web/api/og_test.go` и
  `internal/web/api/og_share_regression_test.go` — только проверка
  соответствия, без изменения поведения.
- Контракт, API и applied-миграции не затрагиваются.
- Аудит: `docs/audits/TIERL-38.md` фиксирует вердикт `ok` и восстановление
  требования.
