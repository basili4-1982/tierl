# Аудит TIERL-47 — Pool smoke 6: repo из проекта

## Контекст

Задача: TIERL-47 (PR 108) — «Pool smoke 6: repo из проекта». Заявлена проверка
TT-148: у воркера нет `REPO` в окружении, а репозиторий приходит в аренде
(lease). Это инфраструктурная проверка пула воркеров, а не поведение сервиса
tierl: ни `docs/SPEC.md`, ни `api/openapi.yaml`, ни `docs/SELF-HOST.md`, ни
живые спеки OpenSpec не описывают пул воркеров, аренду репозитория или
переменную `REPO`. Поэтому у задачи нет живой цепочки «цель → спека → код».

## Вердикт

- TIERL-47: gap — заявленная проверка TT-148 «воркер без `REPO` в env, repo из аренды» в коде отсутствует: нет воркера пула, lease-клиента и smoke-теста; `pool-smoke.txt:1` содержит только маркер `smoke` и проверку не реализует.

## Что заявлено и что найдено

### Заявлено

Воркер запускается без переменной `REPO` в окружении, репозиторий получает из
аренды (lease), и это проверяется smoke-тестом.

### Найдено

- `pool-smoke.txt:1` — файл со строкой `smoke`. Он не запускает воркер, не
  читает окружение и не обращается к аренде; это маркер, а не проверка TT-148.
- Поиск по `REPO`, `TT-148`, `lease` и «аренд» не находит кода или теста,
  связанного с пулом воркеров. Совпадения `release`/`releases` относятся к
  освобождению ресурсов и npm-пакетам, а не к аренде репозитория.
- Единственный `worker` в коде — `internal/platform/mailer/async.go:worker`
  (строка 163), фоновый отправитель писем. Это не воркер пула и не работа с
  `REPO`/арендой.
- `internal/platform/config/config.go:Load` (строка 126) читает переменные
  `TIERL_*`; `REPO` среди них нет, и проверки «репозиторий пришёл из аренды»
  тоже нет.
- Smoke-цели `Makefile:63:smoke` и `.github/workflows/ci.yml:71` проверяют
  `docker compose` и пробы `/healthz`/`/readyz`. Это требование capability
  `self-host` (запуск одной командой), а не pool smoke и не TT-148.

## Gap

Заявлено: smoke-проверка TT-148, в которой воркер стартует без `REPO` в
окружении и получает репозиторий из аренды. В коде этого нет:

- нет воркера пула или точки его запуска, которую можно поднять без `REPO`;
- нет lease-клиента и чтения репозитория из аренды;
- нет smoke-теста, который выставляет окружение без `REPO`, запускает воркер и
  проверяет, что репозиторий пришёл из аренды;
- `pool-smoke.txt:1` — только маркер `smoke`, он не заменяет ни один из
  перечисленных артефактов.

Это gap закрытой задачи: работа заявлена, но артефактов реализации в
репозитории нет.

## Excess

- `pool-smoke.txt:1` — избыточный файл-маркер: он не следует ни из
  `docs/SPEC.md`, ни из `api/openapi.yaml`, ни из ADR, ни из живых спек
  OpenSpec и не реализует TT-148. Это отдельный excess-артефакт PR 108; он не
  заменяет gap выше.
- Другого избыточного кода в границах TIERL-47 не найдено: mailer-worker и
  self-host smoke относятся к своим требованиям.

## Решения

1. **gap → change на восстановление требования и задачи на реализацию.**
   Создан `openspec/changes/restore-pool-smoke-check` с capability
   `worker-pool`. В `specs/worker-pool/spec.md` восстанавливается требование
   TT-148, а в `tasks.md` вынесены задачи: поднять воркер без `REPO`, получать
   репозиторий из аренды и добавить smoke-проверку, которая это подтверждает.
   Код и тесты в границах аудита не меняются.
2. **excess → change на удаление артефакта.** Создан change
   `remove-pool-smoke-artifact` (`skip_specs: true`) с задачей удалить
   `pool-smoke.txt` из корня репозитория и проверить отсутствие ссылок на него.
   В границах аудита файл не удаляется.
3. **Способность названа новым именем `worker-pool` с обоснованием.** Ни один
   якорь (`accounts`, `tierlists`, `submissions`, `results`, `catalog`,
   `reports`, `sharing`, `author-profile`, `item-images`, `self-host`) не
   описывает пул воркеров и аренду репозитория. `self-host` относится к запуску
   и деплою самого tierl, поэтому привязка к нему была бы ложной. Обоснование
   зафиксировано в `restore-pool-smoke-check/proposal.md`.
4. **Происхождение требования и эскалация.** TT-148 пришла из внешнего
   worker-pool harness. Change `restore-pool-smoke-check` восстанавливает
   требование в этом репозитории; дополнительно его `tasks.md` фиксирует
   сверку формулировки TT-148 с владельцем harness. Эскалация остаётся, но не
   заменяет change на восстановление и задачи на реализацию.
5. **Поведение кода не менялось.** Это аудит и планирующие артефакты, а не
   правка сервиса.

`openspec/changes/remove-pool-smoke-artifact/` и
`openspec/changes/restore-pool-smoke-check/`.
