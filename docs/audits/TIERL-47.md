# Аудит TIERL-47 — Pool smoke 6: repo из проекта

## Контекст

Задача: TIERL-47 (PR 108) — «Pool smoke 6: repo из проекта». Заявлено:
проверка TT-148 — у воркера нет `REPO` в окружении, репозиторий приходит в
аренде (lease). Это не продуктовая способность tierl: ни `docs/SPEC.md`, ни
`api/openapi.yaml`, ни `docs/SELF-HOST.md`, ни живые спеки OpenSpec не
описывают пул воркеров, аренду репозитория или переменную `REPO`.

Происхождение требования в этом репозитории не восстанавливается: это
инфраструктурная проверка внешнего harness пула, а не поведение сервиса tierl.
Поэтому аудит не выдумывает для неё продуктовую capability.

## Вердикт

- TIERL-47: excess — pool-smoke.txt:1 — единственный артефакт PR 108, файл-маркер со значением `smoke`, не следует ни из одного требования; проверки TT-148 (воркер без `REPO` в env, repo из аренды) в репозитории нет.

## Что заявлено и что найдено

### Pool smoke 6 / TT-148

Заявлено: воркер запускается без переменной `REPO` в окружении, а репозиторий
получает из аренды (lease), и это проверяется smoke-тестом.

В workspace нет ни воркера пула, ни lease-клиента, ни smoke-теста,
поднимающего воркер без `REPO`:

- `pool-smoke.txt:1` содержит только строку `smoke`; файл не запускает
  воркер, не читает окружение и не обращается к аренде. Это маркер, а не
  проверка TT-148.
- Поиск по `REPO`, `TT-148`, `lease` и «аренд» не находит кода или теста,
  связанного с пулом воркеров. Совпадения `release`/`releases` относятся к
  освобождению ресурсов и npm-пакетам, а не к аренде репозитория.
- Единственный `worker` в коде — `internal/platform/mailer/async.go:worker`,
  это фоновый отправитель писем, не воркер пула и не работа с `REPO`/арендой.
- `internal/platform/config/config.go:Load` читает переменные `TIERL_*`.
  Отсутствие `REPO` среди них само по себе не является реализацией TT-148:
  проверки «репозиторий пришёл из аренды» в коде нет.
- Smoke-цели `Makefile:63:smoke` и `.github/workflows/ci.yml:71` проверяют
  `docker compose` и пробы `/healthz`/`/readyz`. Это требование capability
  `self-host` (запуск одной командой), а не pool smoke и не TT-148.

### Почему это excess

`pool-smoke.txt` не следует ни из `docs/SPEC.md`, ни из `api/openapi.yaml`,
ни из ADR, ни из живых спек OpenSpec. Он также не доказывает заявленную
проверку TT-148. Значит, это избыточный артефакт, попавший в продуктовый
репозиторий из внешнего пула воркеров, а не часть поведения tierl.

## Gap

Gap относительно продукта не оформляется: TT-148 — проверка внешнего
worker-pool harness, которой нет в этом репозитории. Заявленного «воркера без
`REPO`» и «repo из аренды» здесь не должно быть по спеке продукта, поэтому
восстанавливать это требование в capability tierl было бы неверно.

Внешний gap остаётся: сам smoke-тест TT-148 в этом workspace отсутствует, а
`pool-smoke.txt` его не заменяет. Это вынесено на эскалацию владельцу пула
воркеров.

## Решения

1. **excess → задача на удаление артефакта.** Создан change
   `remove-pool-smoke-artifact` (tooling/docs, `skip_specs: true`) с задачей
   удалить `pool-smoke.txt` из корня репозитория и проверить отсутствие ссылок
   на него. В границах аудита файл не удаляется; код и тесты не меняются.
2. **Gap TT-148 → эскалация человеку.** Проверка «у воркера нет `REPO` в env,
   repo приходит в аренде» относится к внешнему worker-pool harness. В
   продуктовом OpenSpec для неё нет якоря; владельцу пула нужно подтвердить
   TT-148 в репозитории harness, а не в tierl.
3. **Способность не названа по якорям продукта.** Ни `accounts`, `tierlists`,
   `submissions`, `results`, `catalog`, `reports`, `sharing`,
   `author-profile`, `item-images`, ни `self-host` не описывают пул воркеров и
   аренду репозитория. `self-host` ближе всего по смыслу, но описывает запуск
   и деплой tierl, поэтому использовать его было бы ложной привязкой. Change
   удаления артефакта объявлен без spec-дельты (`skip_specs: true`), новое имя
   capability не вводится.
4. **Поведение кода не менялось.** Это аудит и задачи на удаление/эскалацию,
   а не правка сервиса.
