# ADR-004: Go JSON API и React SPA, статика в бинарнике

Статус: принято

## Контекст

Нужен интерактивный интерфейс (перетаскивание элементов по тирам) и простой деплой: один контейнер плюс Postgres. Ссылки на опросы и результаты шарятся в соцсетях, чей краулер не исполняет JavaScript, поэтому OG-теги должны быть в HTML, отданном сервером.

## Решение

- Бэкенд — Go, JSON API по контракту `api/openapi.yaml`.
- Фронтенд — React SPA в `web/`. Сборка происходит в multi-stage Dockerfile, результат встраивается в бинарник через `embed`.
- Один процесс отдаёт и API (`/api/...`), и статику. Для путей SPA возвращается `index.html`.
- Для `/t/<slug>` и `/r/<id>` Go подставляет в `index.html` теги `og:*` и `twitter:*` (название, описание, картинка). Значения экранируются через `html/template` или эквивалент.
- Картинка результата — PNG 1200x630, рендерится на сервере и кэшируется.
- Unlisted-опросы отдаются с `noindex` и не попадают в sitemap.
- Фронтенд разрабатывается на моках по контракту (MSW) параллельно с бэкендом. Контракт меняется отдельными небольшими PR, оба конца подстраиваются.
- Пакеты: `domain` и `similarity` не зависят от HTTP и SQL; хендлеры не содержат бизнес-логики.

## Альтернативы

- Серверный рендеринг (Go templates + htmx): проще SEO, но неудобно для drag-and-drop.
- Next.js/SSR: добавляет Node-рантайм в продакшн, усложняет self-host.
- Раздельный деплой фронтенда и API: два артефакта, CORS и CSRF сложнее; выигрыша для MVP нет.

## Последствия

- Релиз — один бинарник и один образ; фронтенд и бэкенд версионируются вместе.
- Изменение фронтенда требует пересборки образа.
- SEO и шеринг обеспечены только для страниц, где Go подставляет метатеги; остальные страницы SPA краулерам не отдаются осмысленно, и это допустимо.
- Нужны тесты подстановки метатегов (включая экранирование пользовательского текста).
