# ADR-001: метрика сходства ответов

Статус: принято

## Контекст

Продукт показывает участнику, какая доля людей разложила элементы по тирам так же, как он. Нужна метрика, которая:

- сравнивает два ответа и выдаёт число от 0 до 1;
- работает при неполных ответах;
- объяснима пользователю в одном предложении;
- считается без внешних зависимостей и детерминированно.

## Решение

Тиры нумеруются от 0 до T-1 (T >= 2). Для двух ответов A и B берём пересечение размещённых элементов I, `N = |I|`:

```
similarity(A, B) = 1 - sum_{i in I} |ta(i) - tb(i)| / (N * (T - 1))
```

- Знаменатель `N * (T - 1)` — максимально возможная сумма расхождений, поэтому результат лежит в [0, 1].
- Если `N < min_overlap` (по умолчанию 3), сходство не определено и пара не учитывается.
- «Думают как ты» — доля других участников, у которых сходство с ответом P не меньше `threshold` (по умолчанию 0.80, конфиг). Считается по парам, где сходство определено.
- Если ответов в опросе меньше `min_answers` (по умолчанию 20), процент не показывается: «мало данных».
- Реализация — чистые функции пакета `internal/similarity`, без I/O.

Обязательные тесты: симметричность, идентичные ответы = 1, противоположные (крайние тиры) = 0 при T = 2, пустое и малое пересечение, property-тесты на диапазон [0, 1].

## Альтернативы

- Корреляция Спирмена/Кендалла: у тир-листов много совпадающих рангов (ничьи), ранговые коэффициенты ведут себя на них нестабильно и хуже объясняются.
- Косинусное сходство: не различает «сдвинул на один тир» и «на четыре», плохо работает при малых N.
- Точное совпадение: слишком строго, почти всегда около нуля на больших опросах.

## Последствия

- Метрика линейна по расстоянию между тирами: ошибка в два тира вдвое весомее ошибки в один.
- Порог 80% — договорённость по умолчанию, не свойство метрики; меняется конфигом без миграций.
- Подсчёт доли попарный, O(M) на запрос при M ответах. Для MVP достаточно; при росте — кэш агрегатов, без смены определения.
- Изменение формулы меняет все ранее показанные проценты и требует нового ADR.
